# Classic Drop：macOS 界面设计提案

日期：2026-10-28。状态：已公开设计提案；UI 实现待开发。多语言基础已在本机工作区实现一版，尚未随本次文档提交发布。

本轮使用 brainstorming 完善既有规划。需求包含主窗口、导入查重、批量删除和恢复，按跨工作区设计处理；不修改应用代码、依赖、公共接口、数据库或既有公开设计规范。仓库要求的 ui-ux-pro-max 未在当前技能目录中发现，本稿不宣称应用该技能。

## 1. 目标与已确认边界

- 采用最新可核验 macOS 的视觉与交互语言，呈现安静、紧凑、原生的桌面音乐工具。
- 保留列表与专辑浏览、文件/文件夹导入、标签及封面预览、安全弹出和恢复入口。
- 导入时检查队列内及当前 iPod 曲库中的重复，明确证据和用户选择。
- 批量删除支持标题、艺人、专辑、风格、年份、播放列表；检索多选，分批累积同一个删除包，最后一次复核并执行。
- 可恢复删除；音乐原件保留在设备恢复数据中，不立即释放容量。
- 用户新增需求：应用界面支持中文、日语和英语；本稿建议首期中文采用简体中文。
- 本稿中的尺寸、筛选组合、视觉细节和恢复操作限制都是设计建议，不等同于用户已确认每个细节。

## 2. macOS 基线与官方依据

2026-10-28 查询 Apple 的“What's the latest version of macOS?”页面。该查询结果只作为设计记录，不作为发布基线；实施和实机验收时必须重新核对 Apple 当前正式版本，不把 beta 自动作为发布目标。

设计以 Apple 当前 Human Interface Guidelines 的 Liquid Glass、系统工具栏、侧栏、深色模式和辅助功能为参考。关键是系统结构、材料层级和行为协调，而不是给所有区域添加模糊背景。

参考资料：

- Materials：<https://developer.apple.com/design/human-interface-guidelines/materials>
- Toolbars：<https://developer.apple.com/design/human-interface-guidelines/toolbars>

当前 docs/gui-design-language.md 面向上游 iOpenPod，明确采用不透明语义颜色并避免 glass effects；Classic Drop 的 window.py 则使用固定浅色 QSS 和绿色主按钮。新需求与上游不透明材料规则存在差异。本稿建议形成 **Classic Drop 专属的 macOS 外壳设计约定**，保留上游文档，不擅自改变 iOpenPod 全局主题；正式采用前记录该适用范围。

## 3. 三种实现方向的比较（仅规划）

| 方向 | 收益 | 限制 | 建议 |
| --- | --- | --- | --- |
| Qt Widgets + 原生平台样式 + 必要的局部 AppKit 适配 | 保留现有工作流与线程边界，优先使用系统窗口、菜单、字体、选择色 | 最新系统材料、标题栏与辅助功能仍需验证；可能需要原生桥接 | 推荐先验证此方案的保真度 |
| 完全用 QSS 模仿 macOS | 初期视觉调整较快 | 无法承诺真实系统材料与行为完全一致；容易出现浅/深色和焦点差异 | 只作旧系统回退，不作为完全一致的验收依据 |
| SwiftUI/AppKit 原生外壳 + 现有 Python 业务层 | 最接近最新 macOS 控件与系统行为 | 涉及进程/语言边界、打包和大量界面迁移，明显扩大范围 | 若局部适配达不到用户要求，再单独决策 |

用户要求的“一致”作为目标，不在当前 PySide6 技术栈上空口保证像素级一致。原生适配、依赖与架构改动均留到方案审阅后决定。

## 4. 主窗口信息架构

建议默认约 1180 × 760 logical points，保留当前最小 940 × 580 的可用性。以下是设计尺寸建议，不是 Apple 的强制数值；Qt logical pixels 与 macOS points 的实际映射以平台验证为准。

```text
┌ 原生窗口控制 ───── 当前工作区 / 数量 ───── 搜索 / 视图 / 检查器 ┐
│ 侧栏          │ 工作区标题、筛选与操作              │ 检查器     │
│               │                                    │            │
│ iPod 曲库     │ 曲目表 / 专辑网格 / 待导入表        │ 封面与详情 │
│ 待导入   12   │                                    │ 或匹配依据 │
│ 批量删除  8   │                                    │ 或删除包   │
│ 恢复与记录    │                                    │            │
│               ├────────────────────────────────────┤            │
│ 当前 iPod     │ 数量、选中项、当前阶段、主操作       │            │
│ 容量 / 弹出   │                                    │            │
└───────────────┴────────────────────────────────────┴────────────┘
```

- 左侧 200–240：来源列表式导航，默认 216；只在“当前 iPod”显示设备切换菜单、容量和显式安全弹出。一次只加载一个 Active iPod。
- 中间：工作区内容；删除和导入分别有自己的选择集合，切换页面不相互污染。
- 右侧 280–320：可折叠检查器，默认 300；主内容优先得到空间。窄窗口隐藏检查器，通过工具栏按钮打开侧边面板，不能遮住提交操作。
- 顶部用统一标题栏/工具栏取代大字号品牌标题和多排控制。品牌放应用菜单及关于页面，主标题显示“iPod 曲库”“待导入”或“批量删除”。
- 底部使用紧凑工作区操作栏。全局状态保留独立位置；空闲时显示曲数及设备状态，执行时显示实际阶段、进度和可用动作。
- 应用菜单提供关于、设置（仅已有配置）、显示备份与日志、退出；不新增播放器、云服务或全量同步功能。

## 5. 视觉与交互规范

| 项目 | 提案 |
| --- | --- |
| 窗口 | 使用系统真实窗口、标题栏、全屏和交通灯，不在应用里绘制假窗口按钮 |
| 材料 | 导航与工具栏在系统支持时使用原生材料；曲目表、匹配证据、警告文字保持清晰稳定的内容表面 |
| 色彩 | 跟随系统浅/深色与强调色；正文/次要文字/分隔线使用语义颜色，避免固定绿色按钮和纯白面板 |
| 字体 | 使用平台系统字体和中文回退，不捆绑或强行分发 Apple 字体；标题约 17、正文约 13、辅助文字约 11–12 |
| 密度 | 4 点间距节奏；表行约 32–36，常规控件约 28–32；原生控件优先采用系统推荐度量 |
| 图标 | 优先系统语义图标；SF Symbols 的接入及许可单独验证，当前方案不导出或打包符号资产 |
| 表格 | 支持排序、列宽、截断提示、键盘焦点、连续/非连续多选；默认不画满屏网格，不用嵌套卡片包住每一行 |
| 专辑 | 封面约 152–176；标题、艺人、年份/曲数；选中和键盘焦点清晰，多选只在支持的任务中启用 |
| 状态 | 状态文字 + 图标 + 颜色，避免只靠红绿区分；检查失败与“无重复”严格区分 |
| 动效 | 仅短暂的面板、选择及进度反馈，不让转场阻塞操作；尊重减少动态效果设置 |

系统跟随是首要目标，不复制网页式巨大留白、固定主题渐变或全屏毛玻璃。视觉稿中的颜色与透明感只用于表达层级，不是已验证的系统材质实现。

## 6. iPod 曲库

- 工具栏提供“列表 / 专辑”分段控件、当前工作区搜索和检查器开关。
- 默认列：标题、艺人、专辑、时长；风格、年份、专辑艺人、碟/曲号可从列菜单展开。
- 检查器显示封面和只读元数据。批量选择时显示数量与汇总，不伪造共同字段。
- 右键“加入删除包”只改变删除意图，显示轻量确认及包计数；不立即删除。
- 没连接设备时显示连接指引与刷新入口；不展示无来源的历史曲库，也不把空表误标成设备曲库为空。

## 7. 导入与查重

工作区顺序：添加文件/文件夹 → 后台检查 → 处理匹配 → 复核导入 → 执行 → 结果。

- 内容上方显示可点击状态筛选：全部、新增、确认重复、历史记录、疑似重复、检查失败/未完成。数量应与真实队列一致，检查中显示未完成而非 0 重复。
- 表格中“导入勾选”与“行选择”独立：前者决定提交对象，后者决定查看/批量操作对象。
- 右侧默认显示封面和源文件信息；点击重复状态时展示“本次队列 / iPod 曲库”的匹配对象、格式、时长和依据。
- 文案区分“文件内容一致”“历史导入记录匹配”“标签与时长相近”；不把后两者标成已确认相同音频。
- 确认重复默认跳过；历史/疑似匹配默认不选。可显式“仍然导入”、选择组内代表，或批量跳过重复项。检查失败项不能无提示计入正常新增。
- 追加文件、修改搜索或切换状态不会静默重置已做决定；标签编辑后更新候选建议，仍保留内容证据。
- 主操作显示“复核导入（N）…”；复核 Sheet 列出实际将加入数量、跳过数量、显式重复导入数量及空间估算（功能具备后）。之后才出现“导入 N 首”。
- 查重不替换既有曲目、不触发删除，不自动把任何项加入删除包。

## 8. 六维筛选与删除包

工作区顺序：筛选 → 多选 → 分批加入包 → 管理包 → 复核 → 一次执行。

- 顶部搜索输入自由文本；“添加筛选”弹出维度和值选择，已选条件作为可编辑 token 显示，避免六个固定下拉框挤满工具栏。
- 维度：标题、艺人、专辑、风格、年份、播放列表；年份支持范围及缺失值，筛选建议跨维度 AND / 同维度多值 OR。
- 列表显示“匹配 M 首 / 当前选中 N 首”，明确区分“加入所选 N 首”与“加入全部匹配 M 首”。后者必须按当时的匹配集合组包。
- 右侧固定为“待删除清单”，副标题保留用户用词“删除包”。显示去重后的总数、条目、加入来源；同一 Track 多次加入只计一次。
- 支持从包内移出单项/多项、清空；清空只清除意图，不删除设备音乐。切换筛选与工作区不清包；来源设备断开/切换或曲库版本变化则使包失效并明确提示。
- 进入最终 Sheet 前先生成有效 Library Review；包变化则复核失效。普通“复核删除包（N）…”使用强调色，只有最终执行动作使用危险色。
- Sheet 标题“从 iPod 曲库删除 N 首音乐？”；展示曲目明细、影响的播放列表和恢复数据大小；说明“这些音乐会从整个曲库及所有播放列表移除；恢复数据保留在 iPod，不立即释放空间。”
- 最终按钮为“可恢复删除 N 首”，另有“取消”；不将危险动作绑定无条件默认 Return，不用“一键清空设备”等歧义标签。
- “一次全部删除”只代表本次包中的 N 首；不默认选择整个曲库，播放列表筛选也不改成仅移出播放列表。

## 9. 执行、恢复与异常

- 空闲 → 检查中 → 可复核 → 复核中 → 验证/准备 → 发布 → 校验/提交 → 完成，失败时依据事实进入可重试、状态未知或待恢复。
- 复核前保持设备只读。执行中禁用设备切换及会改变提交集合的控件；是否允许切页以不会隐藏全局进度为前提。
- 可安全取消的阶段显示“取消”；发布开始后不能把停止请求呈现成已经回滚，不显示未经确认的完成率或瞬时原子性承诺。
- “恢复与记录”首期只展示底层真实可发现的最近可恢复操作、时间、曲数、保留位置、设备是否可用和“恢复…”；不假设有无限多次回退或永久清理。
- 尚待确认的末次写入顺序限制在 UI 中呈现为阻塞说明与恢复入口，不能先放行后悄悄覆盖恢复数据。
- 设备断开立即撤销旧会话的动作权限；显示“iPod 已断开，本次操作可能尚未完成”，给出重新连接及检查恢复的下一步。
- 恢复完成后重读曲库，更新查重候选并使旧删除包/Review 失效。

## 10. 键盘、辅助功能与兼容

- Cmd+F 聚焦当前工作区搜索；Cmd+O 添加文件；Cmd+A 作用于当前有焦点的列表，不跨越导入队列与删除包。
- Shift 范围选择、Cmd 非连续选择；Escape 关闭筛选 popover/Sheet，不把它映射为不确定阶段的回滚。
- Backspace/Delete 在队列或包内仅移出该集合；曲库中最多进入加入删除包的明确流程，不直接写设备。
- 明确标签、VoiceOver 名称、焦点顺序与选中数；按钮有可见文本或可读名称，不能只靠 hover 暴露关键操作。
- 尊重系统深色、强调色、减少透明度、增加对比度与减少动态效果；减少透明度时使用稳定不透明材料。
- 保持仓库 macOS 12.3 最低版本声明，旧系统使用其支持的原生控件和不透明回退，不承诺旧系统具有最新材料。若要提高最低系统版本，必须另行批准。
- 在当前 Windows 环境可以校对方案与静态稿；真实 AppKit 材料、Retina、VoiceOver、窗口行为和系统设置变化必须在 Mac 实机验证。

## 11. 后续实施顺序与验收（UI 待开发）

1. 审阅此设计；确认 Classic Drop 专属材料规则、原生保真目标及恢复限制，删除范围先补 ADR。
2. 仅做原生外壳技术验证，检查 PySide6 + 平台样式/局部桥接是否达标；不先重写全应用。
3. 建立语义颜色/尺寸/状态组件，迁移窗口、导航和曲库，保留既有行为并验证。
   同阶段建立 Classic Drop 独立翻译目录与语言偏好，新增文案同步覆盖中/日/英，不等到界面写完后再集中替换。
4. 在统一外壳中接入导入查重；覆盖误判、用户选择保留、未完成与失败。
5. 接入六维筛选、组包、Review、可恢复执行与重连；删除恢复能力和 UI 同阶段验收。
6. 使用真实 macOS 对照图验证三语、浅/深色、透明度减少、高对比度、键盘/VoiceOver、940×580 及 Retina；再跑仓库要求的自动化与真实设备小批量验证。

不以静态稿替代运行截图，不以 Qt QSS 近似效果宣称已经达到原生一致。设计验收和设备数据安全验收分别保留证据。

## 13. 简体中文、日语和英语

本节记录 UI 实施和验收要求。首期语言为 English（英文源文案）、简体中文（zh_CN）、日本語（ja_JP）；繁体中文及其他语言暂不包含。多语言实现已有本机未发布增量，仍需独立审查、提交和 macOS 验证。

### 语言选择与默认规则

- 默认“跟随系统”，按 macOS 对应用生效的首选语言列表选择首个受支持语言；zh-Hans / zh_CN / zh-SG 等明确简中匹配简中，ja / ja-JP 匹配日文，en 及其区域变体匹配英文。只有繁中或其他不受支持语言且列表中无其他受支持语言时，使用英文，不误称已支持繁中。
- 在 Classic Drop → 设置 → 通用 → 语言，提供“跟随系统 / 简体中文 / 日本語 / English”；使用语言自称，不用旗帜。设置页入口随当前界面翻译，手动选择持久保存并覆盖系统自动值。
- 简中、日文、英文建议立即更新应用内界面，无需重新连接 iPod。系统拥有的原生对话框、系统菜单和权限提示服从 macOS 的语言与生命周期，不承诺所有系统文字跟随应用热切换。
- 语言偏好属于 Classic Drop 主机端应用设置，不写入 iPod，不复用上游 iOpenPod 的全局语言偏好；具体持久化实现留到实施阶段。

### 覆盖与状态保留

- 覆盖应用菜单、工具栏、列表列名、筛选与状态、空页面、导入/查重/删除复核、恢复与断连提示、可读错误、进度说明、tooltip、可访问名称和辅助说明；日期、数量、容量按所选 locale 呈现，ID/年份筛选值不随显示格式改变。
- 重译所有可见控件、动态状态和模型展示文字；保留导入队列、标签草稿、重复匹配与人工选择、筛选输入、删除包、选中设备、进度/取消和恢复决策。语言切换不能重启 worker、重新提交事务或清空业务状态。
- 用户数据原样显示：曲目名、艺人、专辑、风格、播放列表名、文件名、路径、设备标识、固件内容和原始诊断不进入翻译目录；品牌 Classic Drop、iPod、iPodDB 保持原名。

### 技术方向与验收

上游已有 docs/translations.md 与 Qt QTranslator、Qt Linguist、.ts/.qm 维护方式，可借鉴提取、审核和编译验证。但 Classic Drop 当前启动入口没有翻译管理，现有源文案以中文为主；改为英文 source 需显式整理文案，独立命名 catalog、资源加载和设置。优先采用 Qt 标准工具链；不调用在线翻译，不假设上游德语/西语目录覆盖 Classic Drop。打包时加入简中/日语 .qm 以及所需 Qt 资源；英语使用源文案。
